# Add a reviewable handover to your service

For automation consultants, CRM implementers and AI customer-support delivery teams.

## Material you can reuse

Use the [client delivery checklist](DELIVERY_CHECKLIST.md) in your project documentation. Review [when Prooftask fits](WHEN_TO_USE.md) before choosing it. For an approved real public case, use the [case-study outline](CASE_STUDY_TEMPLATE.md).

## First delivery

1. Choose a [delivery template](https://prooftask.com/specifications?utm_source=partner&utm_campaign=provider_integrations) for the actual work.
2. Agree the scope, exclusions, completion criteria, test evidence and review period with the customer before delivery.
3. Submit the exact delivered version with the materials mapped to those criteria.
4. The authorized buyer accepts, rejects, requests changes or requests missing evidence.
5. Export the issued record when available. Track payment separately.

Start with the [service provider guide](https://prooftask.com/for-providers?utm_source=partner&utm_campaign=provider_integrations). Review [service availability and pricing](https://prooftask.com/pricing) before promising signing or other paid services to a customer.

## Next delivery

Reuse a prior arrangement as a draft. Review and reconfirm its parties, dates, scope and price for every new project. A previous acceptance does not authorize the next agreement.

## Public case studies

Use the existing publication flow only after both parties approve the exact public projection. Exclude private original files, tokens, personal contact information and confidential commercial terms. Publication and withdrawal have their own permissions. Do not describe test/demo work as customer adoption.

A useful case describes the starting problem, agreed criteria, submitted version, buyer decision and reusable template. Outcome claims need actual evidence and permission.

## Optional workflow integration

Use [n8n](../n8n/README.md) or the [Agent API](https://prooftask.com/developers/agent-workflows.md) to prepare deliveries in your existing tools. The buyer's authority and human signing boundaries remain unchanged.
