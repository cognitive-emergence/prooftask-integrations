# Client delivery and acceptance checklist

Copy this document into your project's README or delivery folder. Replace bracketed fields with agreed facts. This is a working checklist, not a signed agreement or evidence of acceptance.

## Before work starts

- [ ] Identify the buyer, supplier and person authorized to decide acceptance.
- [ ] Record the business objective, included scope and exclusions.
- [ ] Agree observable completion criteria and the evidence for each criterion.
- [ ] Agree the review period and how corrections or missing evidence will be handled.
- [ ] Record payment terms separately from acceptance status.

## When the work is ready

- [ ] Identify the exact delivered version, release or workflow export.
- [ ] Map each agreed criterion to actual materials.
- [ ] Explain setup, dependencies, operating limits and known issues.
- [ ] Retain original files and access instructions in the agreed location.
- [ ] Confirm the recipient can access the materials without sharing credentials.
- [ ] Save the prepared delivery identifier before deliberately sending it.

## Buyer review

- [ ] Review the exact submitted version against the agreed criteria.
- [ ] Explicitly record acceptance, rejection, requested changes or missing evidence.
- [ ] Associate any correction with a new exact submitted version.
- [ ] Track payment and any required signing separately.
- [ ] Export and independently verify an issued record when appropriate.
